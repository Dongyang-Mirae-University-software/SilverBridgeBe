================================================================================
  SilverBridge AI 프로젝트 설명서
================================================================================

  이 문서는 SilverBridge 백엔드(프로젝트_설명.txt)와 같은 형식으로,
  AI(영상 인식) 저장소의 구조·기술·작업 흐름을 정리한 설명서입니다.

  저장소 : github.com/Dongyang-Mirae-University-software/SilverBridgeAi
  기준 브랜치 : developing


--------------------------------------------------------------------------------
  1. 이 프로젝트는 무엇인가요?
--------------------------------------------------------------------------------

SilverBridge는 노인(피보호자)과 그 가족(보호자)을 연결하는 돌봄 서비스입니다.

  - 피보호자 (WARD)   : 돌봄을 받는 노인
  - 보호자 (GUARDIAN) : 피보호자를 관리하는 가족/보호자
  - 관리자 (ADMIN)    : 서비스 전체를 관리하는 운영자

이 저장소는 그 중 "AI(영상 인식)" 부분입니다.
피보호자의 생활 공간을 카메라로 비추면, AI 모델이 영상 속에서
"위험 상황"을 자동으로 찾아냅니다.

  현재 감지 대상
  - 화재 / 연기 (Fire / Smoke)
  - 흉기 (Knife / Knife_Handle)

쉽게 말해, "사람 대신 화면을 계속 지켜보다가 불이나 칼이 보이면
즉시 알아채는 눈" 역할을 하는 프로그램입니다.
감지 결과는 향후 백엔드(SilverBridgeBe)와 연동해 보호자에게 알림을
보내는 데 사용하는 것을 목표로 합니다. (현재 저장소 단계에서는 모델
학습과 카메라 실시간 테스트까지 구현되어 있습니다.)

  ※ 백엔드/프론트와의 차이
    - 백엔드(Be)  : 회원·연결·알림 등 데이터를 처리하는 서버 (Java/Spring)
    - AI(이 저장소): 카메라 영상에서 위험 물체를 찾는 모델 (Python/YOLO)


--------------------------------------------------------------------------------
  2. 사용하는 기술 (비유로 이해하기)
--------------------------------------------------------------------------------

  Python          : AI/영상 처리에 가장 널리 쓰이는 프로그래밍 언어.
                    이 저장소의 모든 스크립트(.py)가 Python으로 작성됩니다.

  YOLO (Ultralytics) : "You Only Look Once"의 약자. 사진/영상 한 장을
                    한 번에 훑어서 "무엇이, 어디에 있는지"를 네모 상자
                    (bounding box)로 찾아내는 객체 탐지 모델입니다.
                    이 프로젝트는 ultralytics 패키지의 YOLO26 nano
                    (yolo26n.pt) 모델을 기반(pretrained)으로 사용합니다.
                    "이미 사물을 어느 정도 볼 줄 아는 모델"에 우리 데이터
                    (불·칼)를 추가로 가르치는 방식입니다(전이 학습).

  PyTorch (.pt)   : YOLO가 내부적으로 쓰는 딥러닝 엔진. 학습이 끝나면
                    그 결과(가중치)가 best.pt / last.pt 파일로 저장됩니다.
                    best.pt = 학습 중 성능이 가장 좋았던 시점의 모델.

  OpenCV (cv2)    : 카메라 영상을 읽고, 화면에 네모 상자/글자를 그리는
                    영상 처리 라이브러리. 실시간 테스트에 사용합니다.

  yt-dlp          : 유튜브 영상을 자동으로 내려받는 도구. 학습용 이미지를
                    모으기 위해 영상을 받아 프레임(정지 화면)으로 잘라냅니다.

  Roboflow        : 이미지에 "여기가 불/칼" 이라고 영역을 표시(라벨링)하고
                    train/valid/test로 나눠 내보내 주는 데이터셋 플랫폼.
                    각 데이터 폴더의 data.yaml / README.roboflow.txt가
                    Roboflow에서 내보낸 흔적입니다. (포맷: YOLO26, 640x640)

  데이터셋 3분할  : 모델 학습의 기본 약속
                    - train : 모델이 보고 배우는 문제집
                    - valid : 학습 중 실력을 점검하는 모의고사
                    - test  : 학습이 끝난 뒤 보는 최종 시험


--------------------------------------------------------------------------------
  3. 전체 작업 흐름 (데이터 수집 → 학습 → 테스트)
--------------------------------------------------------------------------------

  AI 모델을 만드는 과정은 아래 4단계로 흐릅니다.

  [1단계] 데이터 수집
    → download_video_frames.py
    → 유튜브 URL을 입력하면 영상을 내려받고(yt-dlp), 일정 간격마다
      한 장씩 프레임을 잘라(OpenCV) extracted_frames/ 에 저장.
    → 코드 상단 frame_interval 값으로 "몇 프레임마다 1장 저장"을 조절
      (현재 30 = 약 1초에 1장 수준). 최근 커밋들이 이 값을 조정한 기록.

  [2단계] 라벨링 / 데이터셋 구성 (Roboflow)
    → 모은 이미지에 불·칼 영역을 사람이 표시하고, train/valid/test로
      나눠 YOLO26 포맷으로 내보냄 → *_training/ , Data/ 폴더로 들어옴.

  [3단계] 모델 학습
    → *ModelLearning.py 스크립트 실행 → yolo26n.pt 기반으로 학습 →
      결과 가중치(best.pt) + 그래프 + results.csv 생성.
    → epochs(학습 반복 횟수)를 30 → 100 → 200 → 500으로 늘려가며 실험.

  [4단계] 실시간 탐지 테스트
    → AISliverBriageCameraTest.py 실행 → 카메라 영상에 학습된
      불 모델 + 칼 모델을 동시에 적용해 화면에 실시간으로 박스 표시.
    → CheckCameraIndex.py 로 사용할 카메라 번호를 먼저 확인.

--------------------------------------------------------------------------------
  5. 모델 학습 (실험 이력과 성능)
--------------------------------------------------------------------------------

  ★ 학습 스크립트는 매우 단순합니다 (예: KnifeModelLearning.py)
      from ultralytics import YOLO
      model = YOLO("yolo26n.pt")              # 기반 모델 불러오기
      model.train(data="...data.yaml", epochs=500)   # 학습 시작

  ★ 성능 지표 읽는 법 (results.csv 마지막 줄 = 최종 성능)
    - precision : 모델이 "위험"이라 한 것 중 진짜 위험인 비율 (오탐 적을수록↑)
    - recall    : 실제 위험 중 모델이 놓치지 않고 잡은 비율 (놓침 적을수록↑)
    - mAP50     : 종합 정확도(IoU 0.5 기준). 1.0에 가까울수록 좋음.
    - mAP50-95  : 더 엄격한 기준의 종합 정확도 (가장 까다로운 지표).

  [ 실험 이력 비교 ]
  ─────────────────────────────────────────────────────────────────────
   실험 폴더                  대상    데이터셋        epoch P     R     mAP50 mAP50-95
   ─────────────────────────────────────────────────────────────────────
   epochs30_train/firetrain   화재    fire           30    0.581 0.550 0.531 0.286
   epochs100_train/train100   화재    fire_training  100   0.668 0.652 0.581 0.332
   epochs30_train/knifetrain  흉기    knife_training 30    0.699 0.570 0.675 0.518
   epochs200_train/knifetrain 흉기    knife_training 216*  0.758 0.500 0.589 0.377
   Train/Knife                흉기    Data/Knife     200   0.875 0.850 0.895 0.715
   Train/Knife500 (★최고)     흉기    Data/Knife     369*  0.882 0.828 0.900 0.728
   ─────────────────────────────────────────────────────────────────────
   * = 조기 종료(early stopping). 더 큰 epochs로 시작했으나 성능이 더 이상
       좋아지지 않아 자동 종료된 지점.

  ▶ 결론
    - 흉기 모델은 클래스를 정리한 Data/Knife(Knife/Knife_Handle)로 학습한
      뒤 성능이 크게 향상됨 (mAP50 0.59~0.68 → 0.90).
    - 현재 최고 성능 흉기 모델 : Train/Knife500/weights/best.pt (mAP50 0.900)
    - 화재 모델 : epochs30_train/firetrain/weights/best.pt (실시간 테스트에서
      현재 사용 중. 100 epoch 버전이 약간 더 높으나 테스트 코드는 30 epoch
      버전을 가리키고 있음 — 추후 교체 검토 여지).

  ※ 학습 산출물(각 train 폴더 내부)
    weights/best.pt, weights/last.pt   학습된 모델 가중치
    results.csv                        epoch별 손실·성능 기록
    args.yaml                          학습에 사용한 하이퍼파라미터
    *.png (results/confusion 등)       성능 그래프 이미지

  ※ 공통 학습 설정(args.yaml 기준): imgsz=640, batch=16, warmup_epochs=3,
    기반 모델 yolo26n.pt.


--------------------------------------------------------------------------------
  6. 실시간 탐지 테스트 (카메라)
--------------------------------------------------------------------------------

  AISliverBriageCameraTest.py — 카메라 한 대에 화재 모델 + 흉기 모델을
  동시에 적용해 화면에 박스를 실시간으로 그려 보여주는 검증용 스크립트.

  [동작 방식]
    1) 화재 모델(best.pt) + 흉기 모델(best.pt) 두 개를 불러옴
    2) cv2.VideoCapture(1) 로 카메라 영상 프레임을 한 장씩 읽음
    3) 두 모델로 각각 추론 → 신뢰도(conf) 0.5 미만은 무시
    4) 클래스별 색/라벨로 네모 상자를 그림
    5) ESC 키(27)로 종료

  [화면 표시 규칙]
    화재 모델 : fire  → 빨간색,  smoke → 파란색
    흉기 모델 : Knife        → 초록색  [주의]
                Knife_Handle → 빨간색  [위험]   (손잡이째 쥔 = 더 위험)

  [버전별 차이]
    - epochs200_train/AISliverBriageCameraTest.py
        흉기 모델 = epochs200_train/knifetrain/best.pt (구버전, 위험도 표시 없음)
    - Train/Knife/AISliverBriageCameraTest.py  (최신)
        흉기 모델 = Train/Knife/weights/best.pt
        Knife/Knife_Handle 에 "주의/위험" 위험도 라벨 추가

  CheckCameraIndex.py — 0~9번 카메라를 차례로 열어 어떤 번호가 실제
    내 웹캠인지 확인하는 도우미. (노트북 내장캠/외장캠이 섞이면 번호가
    바뀌므로, VideoCapture(n) 의 n 값을 여기서 먼저 찾습니다.)

--------------------------------------------------------------------------------
  8. 실행 방법
--------------------------------------------------------------------------------

  1) Python 환경 준비 (가상환경 권장)
     pip install ultralytics opencv-python yt-dlp
     ※ ultralytics 설치 시 PyTorch가 함께 설치됩니다.
       GPU(CUDA) 환경이면 학습이 훨씬 빠릅니다 (CPU만으로도 동작은 가능).

  2) 데이터 수집 (선택)
     python download_video_frames.py
     → 유튜브 URL 입력 → downloaded_videos/ 에 영상,
       extracted_frames/ 에 프레임 저장

  3) 모델 학습
     python Train/Knife/"KnifeModelLearning copy.py"   (예: 흉기 학습)
     python epochs30_train/FireModelLearning.py        (예: 화재 학습)
     → 학습 후 runs/ 또는 지정 폴더에 weights/best.pt 생성

  4) 카메라 번호 확인
     python epochs30_train/CheckCameraIndex.py
     → 열리는 인덱스 중 본인 웹캠 번호를 확인

  5) 실시간 탐지 테스트
     python Train/Knife/AISliverBriageCameraTest.py
     → 카메라 화면에 fire/smoke/Knife/Knife_Handle 박스 표시, ESC로 종료

  ※ 중요 — 경로 문제(반드시 확인)
    학습/테스트 스크립트 안의 경로가 절대경로로 하드코딩되어 있습니다.
      - .py 스크립트     : C:/Users/happy/SilverBridgeAI/...  (Windows 개발 PC)
      - 서버 학습 args   : /home/apps/SilverBridgeSky/...      (Linux 학습 서버)
    다른 환경에서 실행할 때는 data="..." 와 YOLO(r"...best.pt") 경로를
    본인 환경의 실제 경로로 바꿔야 동작합니다.
