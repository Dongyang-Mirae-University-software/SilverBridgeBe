# 복약 시간대를 복용 시각으로 정하기 (2026-10-30)

## 배경

- gosky 실서버에서 시간대 = 점심, 복용 시각 = 01:40인 약이 있어 보호자 화면 시간대 칸이 "점심 | 아침"으로 뒤집혔다(FE #174로 칸 순서는 고정).
- 일괄 등록은 시각으로 시간대를 정하지만(`MedicationTimeSlot.fromDoseTime`), **수정(PATCH)과 단건 등록(POST)은 시간대와 시각을 따로 받아 어긋난 조합을 그대로 저장**했다. FE 수정 창도 "복용 시간" 선택과 "복용 시각" 입력이 따로 움직였다.
- 복약 알림은 (피보호자, 날짜, 시간대, 시각, 회차)로 묶어 보내므로, 같은 시각인데 시간대만 다른 약이 있으면 같은 분에 알림이 두 건으로 나뉜다. (정정 2026-10-30: 처음에 "알림 문구가 틀어진다"고 썼으나 문구는 2026-10-27부터 시간대 이름을 넣지 않는다 - `audit-impact-medication-slot-from-time.md`)

## 결정 (사용자, 2026-10-30)

| 질문 | 결정 |
|---|---|
| FE 수정 창 | 시각을 바꾸면 시간대가 따라가고, 시간대를 고르면 그 시간대의 기본 시각(08·12·19·21시)으로 |
| BE | 수정·단건 등록에서 시간대를 시각으로 다시 정함. 어긋나면 **시각 기준**(400 아님 - 예전 화면 호환) |
| 이미 어긋난 데이터 | 마이그레이션 없음. 다음 수정 때 바로잡힘 |

## 변경 (BE)

| 파일 | 내용 |
|---|---|
| `GuardianMedicationService.create` | `doseTime`이 오면 시간대 = `fromDoseTime(doseTime)`. 없으면 기존처럼 시간대 기본 시각 |
| `GuardianMedicationService.update` | `timeSlot`이나 `doseTime`을 보내면 최종 시각으로 시간대를 다시 정함. 이름·복용량·메모만 보내면 시간대 그대로 |
| `MedicationCreateRequest`·`MedicationUpdateRequest` | Swagger·Javadoc에 규칙 명시 |
| 테스트 | 수정 4건(어긋난 조합, 시각만 변경, 이름만 수정 시 유지, 옛 약 재저장 시 바로잡힘) + 등록 1건. 수정 전 코드에서 4건 실패 확인 |

## 바뀌지 않는 것

- 시각이 바뀌면 당일 발송 기록 삭제·복용 체크 유지(MED-G12 조건 포함), `@DynamicUpdate`, 응답 형식, 일괄 등록
- 시간대만 바꾸면 새 시간대 기본 시각(08·13·18·22시) - 기본 시각은 `fromDoseTime`에서 자기 시간대로 돌아온다
- 마이그레이션 없음

## 수용한 것

- 시간대만 다시 보내도(같은 값이어도) 어긋난 옛 약은 시각 기준으로 바뀐다 - 의도된 보정이다.
- 이미 어긋난 옛 약은 수정되기 전까지 알림 묶음·화면이 예전처럼 보인다(개수는 운영 DB 읽기가 막혀 세지 않았다).
