# 카카오 알림톡 — 이상감지 템플릿 검수 이력

> 알림톡은 **승인된 문구만** 발송할 수 있고 승인 후 문구 수정은 재검수 대상이라, **제출한 원문을 남겨야**
> 반려 대응 시 "무엇을 고쳤는지"를 재구성할 수 있다. 정책·불변 규칙은 `.claude/rules/domain-security-policy.md`.

## 1차 (2026-07-15 제출 → 2026-07-20 반려)

**반려 사유**: 수신 대상과 발송 사유가 불명확. 알림톡은 "수신자의 액션에 기반한 정보성 메시지"만 허용되는데,
사실 전달만 있고 *수신자가 무슨 행동을 했기에 이 메시지를 받는지*가 없었다. 변수 비중이 높아 고정 문구만으로
용도를 판단할 수 없다는 점도 함께 지적("변수만으로 이루어진 내용").

**제출 본문**

```
[CareAI] 이상 감지
#{wardName}님 #{location}에서 #{detectedTypeLabel}이(가) 감지되었습니다.
```

## 2차 (2026-07-20 제출 → 2026-07-23 반려)

**반려 사유 (원문)**

> 상기와 같은 **다발성 메시지**의 경우, 다수의 메시지가 발송될 수 있음에 대해 수신자에게 동의 또는 고지된
> 경우에만 승인 가능합니다. 수신자가 다발성 알림을 동의 및 요청하였음이 확인 가능한 내용을 **메시지 내
> 고정값으로** 기재하여 주시기 바랍니다.
> (예: 해당 메시지는 고객님께서 요청하신 이상 감지 알림으로, 설정하신 내용과 다른 상황이 생길 경우
> 지정하신 보호자 및 피보호자에게 발송됩니다. 등)

수신자 액션(1차 지적)은 해소했으나, 마지막 줄이 "설정에 따라 발송된다"까지만 말해 **회원이 반복 수신을
직접 신청했다는 고지**가 없었다. 심사 가이드상 "수신자의 추가 요청이 없음에도 반복적으로 정보를 발송하는
경우"는 광고성으로 분류된다. 검수자 참고 의견도 **비워둔 채** 제출했다.

**제출 본문**

```
[CareAI] 이상 상황 감지 안내

회원님께서 CareAI에 보호자로 등록하시고 신청하신 이상 감지 알림입니다.

▶ 대상: #{wardName}님
▶ 장소: #{location}
▶ 감지 내용: #{detectedTypeLabel}
▶ 감지 시각: #{detectedAt}

등록하신 카메라에서 위와 같은 상황이 감지되어 안내드립니다.
자세한 내용은 CareAI 앱에서 확인하실 수 있습니다.

※ 본 알림은 회원님이 설정하신 알림 수신 설정에 따라 발송되며, 앱 내 알림 설정에서 변경하실 수 있습니다.
```

## 3차 (2026-07-23 제출, **검수중**)

**2차 대비 변경점**

1. **다발성 수신 동의 고지 추가**(반려 사유 정면 대응) — 검수자가 제시한 예시 문장을 거의 그대로 사용.
   "…감지될 **때마다** 지정하신 보호자 및 피보호자에게 발송됩니다 / 상황이 반복될 경우 알림이 **여러 건**
   발송될 수 있습니다." 전부 **고정 문구**(변수로 넣으면 검수 시점에 확인 불가라 인정되지 않는다).
2. `※ 본 알림은 … 설정에 따라 발송되며` 줄을 위 고지로 **교체**(중복 제거).
3. `자세한 내용은 CareAI 앱에서 확인하실 수 있습니다` **삭제** — 반려 항목 "앱 설치를 유도하는 내용"에 걸릴
   여지 제거. 앱 언급은 수신 설정 변경 안내 한 줄로 한정.
4. "신청하신" → "**직접** 신청하신" (수신자 능동성 강조).
5. **검수자 참고 의견을 채움** — 변수 예시값·발송 대상·동의 획득 경로·채널 브랜드 관계.

**제출 본문** (275자 + 변수내용 / 1,000자)

```
[CareAI] 이상 상황 감지 안내

회원님께서 CareAI에 보호자로 등록하시고 직접 신청하신 이상 감지 알림입니다.

▶ 대상: #{wardName}님
▶ 장소: #{location}
▶ 감지 내용: #{detectedTypeLabel}
▶ 감지 시각: #{detectedAt}

본 알림은 회원님께서 요청하신 이상 감지 알림으로, 등록하신 카메라에서 설정하신 내용과 다른 상황이 감지될 때마다 지정하신 보호자 및 피보호자에게 발송됩니다.

상황이 반복될 경우 알림이 여러 건 발송될 수 있습니다.

수신을 원하지 않으시면 CareAI 앱 알림 설정에서 언제든지 변경하실 수 있습니다.
```

**제출한 검수자 참고 의견** (수신자에게 노출되지 않음)

```
CareAI는 가정 내 카메라 AI가 낙상·화재 등 이상 상황을 감지해 보호자에게 알리는 시니어 돌봄 서비스입니다.

발송 대상: 앱에서 피보호자와 보호자 관계를 맺고(양측 수락) 알림톡 수신을 직접 ON으로 설정한 회원에 한합니다. 앱 내 '알림 설정'에서 언제든 해제 가능하며, 광고성 발송은 없습니다. 다발성 수신에 동의했음이 확인 가능

발송 시점: 등록된 카메라가 이상 상황을 감지한 시점에만 발송됩니다.

변수 예시
wardName: 홍길동
location: 거실
detectedTypeLabel: 낙상
detectedAt: 2026-07-23 14:30

발신 채널 @gosky는 CareAI(SilverBridge) 운영사의 공식 채널입니다.
```

> ⚠️ 참고 의견의 "다발성 수신에 동의했음이 확인 가능"은 문장이 끊겨 있다(원래 의도는 "알림 신청 시 상황이
> 감지될 때마다 반복 발송된다는 점을 앱에서 안내하고 동의를 받습니다"). 본문 고정 문구가 요구사항을 충족하므로
> 그대로 두되, **4차 반려 시 이 문장부터 완성**할 것.

## 남은 작업

- **`#{detectedAt}` 코드 반영** — 2026-07-23 완료(아래 "코드 연동" 참조). 반영 전이었다면 승인돼도
  `bindVariables()`가 빈 문자열을 채워 "감지 시각: "만 발송됐다.
- **피보호자 본인용 템플릿 미등록** — 현재 리스너는 보호자·본인 양쪽에 같은 알림을 보내는데, 본인에게
  "OOO님 / 대상: OOO님"은 문구가 어긋난다. 별도 템플릿 등록 + `AlimtalkProperties.templateFor()`의
  종류별 단일 매핑 구조 확장이 필요(리스너에 `self` 플래그는 이미 있음). 다발성 고지 문구도 동일하게 필요.
- **브랜드 표기 3중화** — 채널 `@gosky` / 템플릿명 `SilverBridge` / 본문 `CareAI`. 검수자에겐 서로 다른
  주체로 보인다. 대외 서비스명을 하나로 정리하는 것이 안전하다(참고 의견으로 임시 방어 중).
- **승인 후**: `.env.dev`에 `ALIMTALK_ENABLED=true` · `ALIMTALK_PF_ID` · `ALIMTALK_TEMPLATE_ANOMALY` 주입
  (승인 시 실제 템플릿 ID를 콘솔에서 재확인 — 수정 제출이라 ID가 유지될 것으로 보이나 확정은 아니다).

## 코드 연동 (`#{detectedAt}`)

| 위치 | 내용 |
|---|---|
| `AnomalyDetectedEvent` | `OffsetDateTime detectedAt` 추가 — AI `analyzedAt` 값 그대로(**nullable**) |
| `AnomalyDetectionService` | 발행 시 `signal.analyzedAt()` 전달 |
| `AnomalyNotificationListener` | `data["detectedAt"]` = KST `yyyy-MM-dd HH:mm` 문자열 |
| `application.yaml` | `variables: [wardName, location, detectedTypeLabel, detectedAt]` |

- **표시용 폴백**: AI fallback 페이로드엔 `analyzedAt`이 없어 `detectedAt`이 null일 수 있다. 이때 문구에
  빈 칸이 나가지 않도록 **발송 시각**으로 대체해 표시한다(알림 발송은 감지 직후라 오차가 초 단위). 이력
  `anomaly_event.detected_at`은 **NULL 그대로** 둔다 — "AI가 알려준 시각"과 "우리가 받은 시각"의 구분은
  이력에서만 유지한다.
- **타임존**: AI `analyzedAt`은 naive UTC에 UTC 오프셋을 부여한 값이라, 표시 직전 `Asia/Seoul`로 변환한다
  (컨테이너 `TZ`에 의존하지 않고 명시적으로).
