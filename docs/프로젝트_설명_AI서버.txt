--------------------------------------------------------------------------------
  1. 이 프로젝트는 무엇인가요?
--------------------------------------------------------------------------------

SilverBridge는 노인(피보호자)과 그 가족(보호자)을 연결하는 돌봄 서비스입니다.
그중 "AI 서버"는 SilverBridge 생태계에서 AI 기능을 독립적으로 담당하는
별도 서버 프로그램입니다.

  [전체 시스템에서의 위치]
    보호자 앱 / 피보호자 앱   ─(REST/Socket)→  API 서버(SilverBridgeBe)
    iPad(카메라 송출 앱)      ─(프레임 업로드)→  AI 서버(이 저장소)
    API 서버                  ─(REST/WS)──────→  AI 서버
    AI 서버                   ─(프록시)────────→  의료 챗 서버 / 예약 API
    AI 서버                   ─(저장)──────────→  PostgreSQL

  즉 AI 서버는 사용자 앱과 직접 통신하지 않는 "내부 전문 서비스"입니다.
  카메라 영상 분석, 의료 챗 응답, 예약 오케스트레이션을 담당하고, 그 결과를
  REST/WebSocket으로 API 서버·프론트에 제공합니다.

  [AI 서버가 하는 일]
    - iPad가 올리는 실시간 영상 프레임에서 화재/연기를 감지(YOLO 추론)
    - 감지 결과를 자체 WebSocket으로 구독자에게 실시간 broadcast
    - 모델/카메라 메타데이터 관리, 분석 결과 조회
    - 의료 챗(증상 → 위험도/권장행동) 및 병원 예약 흐름 중개
    - 위 기능을 REST + WebSocket + Swagger로 제공

  [AI 서버가 하지 않는 일 — 책임 분리]
    - 보호자/피보호자 앱 직접 연동, 사용자 알림(FCM/SMS/푸시) 발송
    - 사용자 인증·인가 (AI 서버는 서버 간 API Key 한 겹만 검사)
    - 감지 결과를 "누구네 보호자에게" 전달하는 로직 (그건 API 서버 몫)

  3. 사용하는 기술
--------------------------------------------------------------------------------

  Python 3.11        : 서버 구현 언어.
  FastAPI / Uvicorn  : 웹 API 프레임워크 + ASGI 실행기. REST와 WebSocket을 함께
                       제공하고 Swagger 문서를 자동 생성.
  SQLAlchemy         : 파이썬 객체 ↔ DB 테이블 매핑(ORM).
  PostgreSQL 17      : 운영 데이터베이스(컨테이너 silverbridge-ai-postgres).
                       (옛 MVP는 SQLite였으나 운영은 PostgreSQL로 전환됨)
  Pydantic           : 요청/응답 JSON 형식·값 검증.
  Ultralytics YOLO   : 영상 객체 탐지 모델(YOLO26). fire_smoke.pt 등 .pt 가중치를
                       로드해 프레임에서 화재/연기를 탐지. GPU(CUDA)로 추론.
  OpenCV / torch     : 프레임 디코딩·영상 처리 / 딥러닝 엔진.
  transformers·GPT   : 의료 챗(MedGemma) 및 구조화 응답(gpt-4o-mini) 연동.
  Docker             : 컨테이너 실행(GPU 패스스루, network_mode host).
  Swagger / OpenAPI  : 자동 생성 API 명세 — /api/docs, /api/redoc, /api/openapi.json.

  ★ 인증은 사용자 로그인(JWT)이 아니라 서버 간 단일 API Key(X-API-Key)다.
    "API 서버가 호출하는가"만 확인하는 내부 서비스 전제. (상세 §10)

  5. 라이브 스트림 & 이상감지 파이프라인 (핵심 기능)
--------------------------------------------------------------------------------

  iPad가 카메라 프레임을 올리면, AI 서버가 이를 분석해 결과를 실시간으로
  구독자에게 흘려보낸다.

  [iPad 송출 앱]
     │ ① POST /api/v1/stream-sessions
     │      {sessionId, cameraIdentifier, deviceType:"ipad"}     ← 세션 생성
     │ ② POST /api/v1/stream-sessions/{sessionId}/frame (JPEG)   ← 매 프레임 반복
     ▼
  [AI 서버]
     • 프레임을 메모리(frame_store)에 저장 + fps/lastFrameAt 갱신
     • analyze_stream_frame: N프레임마다(운영 N=5) fire_smoke.pt로 추론,
       결과를 session_analysis_store(메모리)에 캐시
     • 매 프레임마다 해당 sessionId 구독자에게 broadcast:
         {session_status} + {latest_analysis}
     ▼
  [WS /api/v1/ws/live]  구독자(보호자 웹 등)에게 실시간 푸시

  [동작 성질 — 코드로 확인]
    - 감지 종류는 화재/연기(fire/smoke) 전용. (낙상·흉기 모델은 학습 중이나
      라이브 경로 미탑재 — .env 플래그만 존재)
    - 라이브 분석 결과는 DB에 저장하지 않는다(메모리 캐시만). 실측상
      analysis_results 테이블 0행.
    - broadcast는 매 프레임마다 발생(초당 여러 번), 분석 재계산만 N프레임마다.
      → 같은 analyzedAt 결과가 반복 broadcast될 수 있음.
    - 세션 상태는 STREAM_STATE_BACKEND=memory (실측) → 메모리 관리. 서버
      재시작 시 진행 중 세션 정보는 사라짐.
    - 무프레임 LIVE_STREAM_DISCONNECT_TIMEOUT_SEC(기본 10초) 초과 시 세션
      status=disconnected 로 전환.


--------------------------------------------------------------------------------
  6. WebSocket API (/api/v1/ws/live)
--------------------------------------------------------------------------------

  [ 6-1. 인증 ]
    x-api-key 헤더  또는  ?apiKey= 쿼리 ( .env API_KEY 단일 정적 키 ).
    불일치 시 close(1008, "AUTH_INVALID_KEY").
    ※ 쿼리 방식은 접속 URL 로깅 시 키가 노출되므로 헤더 방식이 안전.

  [ 6-2. 클라이언트 → 서버 (action) ]
    연결 직후 서버가 {"type":"connected"} 전송. 이후 action:
      {"action":"ping"}                        → {"type":"pong"}
      {"action":"list"}                        → {"type":"live_streams","data":[...]}
      {"action":"subscribe","sessionId":"..."} → subscribed → session_status →
                                                 latest_analysis (스냅샷 1회)
      {"action":"unsubscribe","sessionId":"..."} → unsubscribed
    ※ latest_analysis는 "구독한 세션"에만 온다. live_streams(세션 목록)는 전체
      연결에 broadcast(세션 생성/종료 시).

  [ 6-3. 서버 → 클라이언트 신호 ]

    ① session_status (세션 헬스)
       { "type":"session_status", "sessionId":"stream_009",
         "data":{ "status":"running|stopped|disconnected",
                  "lastFrameAt":"...|null", "fps":12.0,
                  "viewerCount":1, "isAnalyzing":true } }

    ② latest_analysis (분석 결과)
       { "type":"latest_analysis", "sessionId":"stream_009",
         "data":{
           "detectedType":"fire",     // normal | fire | smoke | unknown
           "confidence":0.4547,       // YOLO score (최고 confidence 객체)
           "danger":false,            // 표시 전용 — 라이브 경로에서 항상 false
           "detections":[ {"detectedType":"fire","confidence":0.4547,
                           "bbox":{"x1":..,"y1":..,"x2":..,"y2":..}} ],
           "analyzedAt":"2026-05-30T10:20:22.939247"   // naive UTC
         } }

       ※ danger 필드는 판정값이 아니라 더미(표시 전용)다. detect_from_jpeg
         docstring "danger 는 항상 False (표시 전용)", analyze_stream_frame도
         "danger":False 하드코딩. 위험 판단은 detectedType + confidence로.
       ※ 캐시 없을 때 fallback 스키마는 {detectedType, confidence, danger}만
         올 수 있음(detections/analyzedAt 없음).
       ※ 모델 추론 임계 FIRE_SMOKE_CONF_THRESHOLD 기본 0.35 (낮음 = "표시"용).
         unknown = 프레임 없음/모델 미로드/디코드 실패(에러 상태).

  7. REST API 요약 (Swagger: /api/docs)

  [ 라이브 스트림 ]

    (ws) /api/v1/ws/live                                실시간 구독(§6)

  [ 모델 / 카메라 / 분석(구 경로) ]

    /api/v1/analysis/**  단일 이미지 분석 / (구) 카메라 RTSP 스트림 분석·결과 조회
                         ※ 라이브(iPad) 경로와 별개인 구 경로.

  [ 의료 챗 / 예약 ]
    /api/v1/chat/**      증상 → 위험도/권장행동. 뒤로 ChatSilverBridge(6012) 프록시.
    /api/v1/reservation-credential/**  예약 자격증명 저장(예약 API 6015 연동).
    (예약 흐름)          챗에서 SilverBridgeReservation(6015) 오케스트레이션.

  [ 기타 ]
    /api/v1/game/**      인지 게임 임베드 (무인증)

  ※ 라우터별 인증: health·game·(ws)live 는 무인증(단 ws는 자체 apiKey 검증),

--------------------------------------------------------------------------------
  8. 데이터베이스 테이블 (PostgreSQL)
--------------------------------------------------------------------------------

  ※ 라이브 분석 결과는 DB에 안 남는다(메모리 캐시). 아래는 메타/구 경로 테이블.
  ※ 시간은 UTC, 컬럼 snake_case.

  [ cameras ] — 분석 대상 카메라
    id, camera_no, identifier, name, stream_url,
    stream_type(rtsp/http_mjpeg/droidcam),
    target_user_id(피보호자 식별자·문자열), guardian_user_id(보호자·문자열),
    location_name(예 "거실"), is_active, created_at, updated_at
    ※ target_user_id/guardian_user_id 는 AI가 검증 안 하는 자유 문자열
      (연동 편의용 보관). 실측상 현재 비어 있음.

  [ analysis_results ] — (구) 분석 결과. 라이브는 미기록.
    id, analysis_no, camera_id/identifier, model_id/identifier,
    detected_type(fall/fire/weapon/normal/unknown), confidence, danger,
    snapshot_path, raw_result_json, analyzed_at, created_at

  [ ai_models ] — 모델 메타데이터
    id, model_no, identifier, name, type, file_path, framework, version,
    description, threshold(기본 0.75), is_active, created_at, updated_at

  [ stream_sessions ] — iPad 송출 세션(상태 backend=db일 때)
    session_id, camera_identifier, device_type,
    status(running/stopped/disconnected), started_at, last_frame_at,
    stopped_at, fps, viewer_count, is_analyzing

  [ chat_logs ] — 의료 챗 기록
    id, chat_no, user_id, message, context_json, reply,
    risk_level(low/medium/high), recommended_action, reservation_required, created_at


--------------------------------------------------------------------------------
  9. 감지 모델 학습 (배경)
--------------------------------------------------------------------------------

  감지 .pt 파일은 별도 학습 저장소에서 만든다.
  기술: Python + Ultralytics YOLO26 + OpenCV + Roboflow(라벨링) + yt-dlp(수집).

  ▶ 감지 대상 : 화재/연기(Fire/Smoke), 흉기(Knife/Knife_Handle), 낙상(fall)
                ※ 서버 라이브 경로 실제 탑재 = fire/smoke.
  ▶ 방식      : yolo26n.pt(사전학습) 기반 전이학습. 데이터셋 train/valid/test 3분할.
  ▶ 흐름      : 영상 수집 → 라벨링(Roboflow, YOLO26 640x640) → 학습(epochs
                30→100→200→500) → 카메라 실시간 탐지 테스트.
  ▶ 성능 지표 : precision(오탐↓) / recall(놓침↓) / mAP50 / mAP50-95.
  ▶ 흉기 실험 결론 : 클래스 정리(Knife/Knife_Handle) 후 mAP50 0.59~0.68 → 0.90
                   (최고 Data/Knife 500epoch, mAP50 0.900).
  ▶ 화재 모델 : epochs30 firetrain/weights/best.pt 계열.
  ▶ 저장소    : SilverBridgeAi(데이터셋·학습), AiSilverBridgeSky(fire_smoke·weapon),
                SilverBridgeJH(낙상). §2 참고.
  ▶ 주의      : 학습 스크립트 경로가 절대경로 하드코딩(Windows PC / Linux 학습서버).
                대용량 .pt·이미지 → Git LFS 미도입.
