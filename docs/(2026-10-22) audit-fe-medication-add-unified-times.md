## 이슈

🔴 0 · 🟠 0 · 🟡 1 · 🟢 5

### 🟡 M-1 서버가 응답한 5xx·408도 "확인 필요"로 다뤄야 한다
- 위치: `MedicationAddModal.tsx:234`(`axios.isAxiosError(error) && !error.response`만 결과 불명으로 봄)
- 재현(코드 확인): FE 중계 `src/app/api/[...path]/route.ts`는 BE 호출에 예외 처리가 없어, BE가 커밋한 뒤 응답 전에 연결이 끊기면 Next가 500을 준다. 앞단 nginx 시간 초과는 504. 이 응답들은 지금 "서버가 거절한 실패"로 분류돼 [등록]이 다시 열리고, BE는 다른 요청의 같은 이름을 막지 않아 중복 등록된다. 일괄 등록이 수 ms라 드문 경우.
- 제안: 408·5xx(500·502·503·504)는 결과 불명으로 보고 "확인 필요" 안내(다시 보내지 않음), 4xx만 고쳐서 다시 등록. 테스트: 504 응답 뒤 재전송 없음.
- 출처: 독립 에이전트(🟠) → 메인이 중계 코드로 경로 확인, 발생 빈도를 반영해 🟡.

### 🟢 L-1 죽은 코드
- `MedicationAddModal.module.css:386·395·408` `.doneBadge`·`.uncertainBadge`·`.errorNote` 사용처 없음(#88의 줄별 설계 잔재). `MedicationDraftForm`의 `disabled` prop은 모달이 늘 `false`(`MedicationAddModal.tsx:404`).

### 🟢 L-2 [등록]이 왜 꺼졌는지 알려주지 않는다
- 칩을 모두 끄면 [등록]만 비활성이고 안내가 없다. 제안: 칩 0개일 때 "시간을 하나 이상 골라 주세요". 1초 잠금은 짧아 안내 불요.

### 🟢 L-3 잠금이 포커스된 [등록]을 끄면 포커스가 body로 빠진다
- E4로 확인. `useModalDialog`의 document 처리로 Tab·Esc는 동작하지만 화면 읽기 위치가 사라진다. 제안: 잠금 시작 때 포커스가 [등록]이면 단계 제목으로 옮긴다.

### 🟢 L-4 테스트 공백(변이로 확인)
- 다시 찍기 성공 시 선택 초기화 / 섞임 기준(최빈 ≠ 최대: 예 2·2·3) / 1단계 화면 켜짐 음성 / 화면 켜짐 테스트에서 `visibilityState`를 명시하지 않음 / 1단계 Enter → 2단계 진입만 하고 등록되지 않음.

### 🟢 L-5 안내 문구의 한계
- 아는 횟수가 한 가지뿐이면 직접 넣은 약(횟수 모름)이 있어도 "봉투에는 하루 N번이에요"가 전체에 해당하는 것처럼 읽힌다. 횟수가 섞이고 공통 횟수가 5번 이상이면 "4번까지 고를 수 있어요"가 빠진다. 수용 가능 - 문구를 "봉투에 적힌 약은 하루 N번이에요"로 좁히는 정도 권장.

### 채택하지 않은 에이전트 지적
- "같은 순간 Enter+클릭으로 2회 전송" - React가 클릭·키 같은 이산 이벤트 뒤 상태를 바로 반영하고(E1·직전 점검), 2단계엔 텍스트 입력이 없다. 이론상 가능성만 있어 이슈로 두지 않음.
- 데스크톱 창 전환(화면 켜짐 이벤트 없음)은 잠금 대상이 아님 - 사고 원인이 휴대폰 화면 깨우기라 수용(에이전트도 수용 의견).
