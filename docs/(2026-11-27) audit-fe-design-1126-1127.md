## 1. I-2 조치 (FE #373)

- **원인:** 2단계 `canGoNext`가 `Boolean(wardRelation)`만 봤다. 회원 ID 확인이 늦게 "요청할 수 없음"으로 와도 [다음]이 열려 있어, 3단계로 갔다가 보내기에서 막혔다.
- **수정:** 2단계 `canGoNext`에 `!idBlocked`를 더했다. Enter도 같은 값을 따른다. 오류 상자·[회원 ID 바꾸기]·3단계 동작은 그대로다.
- **테스트:**
  - H-2 테스트를 "2단계 [다음]·Enter(폼 제출)가 막힌다"로 바꿨다.
  - [회원 ID 바꾸기]를 누르면 깊이 0이 되고, ID를 바꾸면 [다음]이 다시 열리는지 함께 본다.
  - 3단계에서 늦게 막히는 경우를 테스트로 따로 둔다.
  - 변이 검사: `!idBlocked`를 지우면 새 테스트가 실패한다.
- **gosky 실측(develop `319e585`):** 미리보기 GET만 4초 늦은 `USER_NOT_FOUND`로 바꾸고, GET이 아닌 요청은 모두 막았다.
  - 2단계에서 "엄마"를 골라도 [다음]이 막혀 있다. 폼 제출로도 2단계에 머문다.
  - [회원 ID 바꾸기]를 누르면 1단계(깊이 0)가 되고, 고른 호칭은 남는다.
  - 뒤로 가기 한 번이면 이전 페이지(`/guardian/notices`)로 나간다.
  - 서버로 나간 쓰기 요청은 0건이다.
