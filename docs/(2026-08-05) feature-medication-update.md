# 약 수정 API (2026-08-05)

> 등록·삭제는 있었지만 **수정이 없어** 오타 하나에도 삭제 후 재등록해야 했고, 그러면 지난 복용 이력이
> 새 약과 끊어졌다. OCR 인식 결과를 사용자가 고쳐 저장하는 흐름(다음 과제)의 전제이기도 하다.
> 이전 문서: `docs/(2026-08-04) feature-medication-reminder.md` 외 2편

---

## 1. 엔드포인트

```
PATCH /api/guardian/medication/{medicationId}
바디: { name?, timeSlot?, doseTime?, doseAmount?, memo? }   // 모두 선택, null = 미변경
응답: MedicationItem (오늘 복용 체크 상태 포함)
```

`PATCH` + "null은 미변경"은 `WardCameraController`의 부분 수정 관례를 그대로 따랐다.

**`wardId`·`createdBy`는 불변**이다 — 소유자와 등록자는 약의 정체성이라, 다른 피보호자에게 옮기려면 삭제 후 재등록한다.

**마이그레이션 없음** — 기존 스키마로 충분하다.

---

## 2. 새로 정한 두 가지 규약

### 시간대만 바꾸면 시각도 따라간다
"아침 08:00"을 **저녁으로만** 바꾸면 08:00이 남아 **"저녁 08:00"** 이라는 이상한 상태가 된다. 그래서 `timeSlot`이 바뀌었는데 `doseTime`을 주지 않으면 **새 시간대의 기본 시각**으로 갱신한다(저녁 → 18:00). 등록 때의 "시각 생략 시 슬롯 기본값" 규칙의 연장이다.

- `doseTime`을 명시하면 그 값을 쓴다(기본값으로 덮어쓰지 않는다).
- **같은 시간대를 다시 보내면 시각은 유지**한다 — 07:30으로 맞춰 둔 아침 약이 08:00으로 되돌아가면 안 된다.

### 메모는 빈 문자열로 지운다
`null`이 "미변경"이라 `null`로는 메모를 삭제할 수 없다. **빈 문자열**을 보내면 `null`로 저장된다(메모 없음). 반대로 **이름은 공백만 보내면 기존값을 유지**한다 — 빈 이름으로 덮어쓰면 목록에서 무슨 약인지 알 수 없게 된다.

---

## 3. 복용 시각이 바뀌면 당일 알림을 다시 보낸다

`doseTime`이 **실제로 바뀐 경우에만** 그 약의 **당일 발송 기록(attempt 1·2)을 삭제**한다 → 새 시각 기준으로 다시 판정되어 알림이 나간다.

이게 없으면 보호자가 "아침 08:00 → 저녁 20:00"으로 고쳤을 때, 이미 08:00 발송 기록이 남아 있어 **오늘 저녁에는 알림이 울리지 않는다.**

- **복용 체크(`medication_intake`)는 건드리지 않는다** — 이미 드신 약은 여전히 울리지 않고, 응답의 `taken`도 그대로다.
- 이름·메모만 바꾼 경우에는 발송 기록을 **건드리지 않는다**(불필요한 중복 알림 방지).
- 2차의 "선점 후 발송" 규칙은 그대로다 — 기록을 지우는 것은 수정이라는 명시적 사용자 행위에 한정된다.

## 4. 인가·에러

| 상황 | 응답 |
|---|---|
| 보호자 아님(WARD/ADMIN) | 403 (클래스 레벨 `@PreAuthorize`) |
| ACTIVE 연결이 아닌 피보호자의 약 | 403 `MEDICATION_NOT_AUTHORIZED` + `[IDOR-ATTEMPT]` WARN |
| 없는 약 / 삭제된 약 | 404 `MEDICATION_NOT_FOUND` (연결 확인 전에 차단) |
| 길이·범위 위반 | 400 |

새 `ErrorCode`는 필요 없었다. **수정도 보호자 전용**이라 역할 분리 규칙(불변 규칙 ①)이 그대로 유지된다 — 피보호자는 자기 약도 고칠 수 없다.
