# 약 봉투 OCR 측정 결과 (2026-10-22)

> 시안의 "카메라로 약 봉투를 찍으면 자동 등록"을 만들 수 있는지 보려고, Claude가 약 봉투 사진에서 복약 정보를 얼마나 정확히 뽑는지 측정했다.
> **결론: 조건부 Go - `claude-sonnet-5-5`(effort low)로 진행한다(사용자 결정 2026-10-22).**

## 1. 방법

- **입력**: 실제 약 봉투·복약 안내문 사진 2장(① 감기약 6종, ② 진통·근이완제 4종). 두 장 모두 옆으로 누운 휴대폰 사진이다.
- **변형**: 원본 그대로 / 바로 세움(90° 회전) / 긴 변 1024px 축소, 각 사진마다 3가지. 거절 확인용으로 약과 무관한 합성 메모 이미지 1장을 추가했다.
- **모델**: `claude-opus-5-5`·`claude-sonnet-5-5`·`claude-haiku-5-5`. 모두 effort `low`, 구조화 출력(JSON 스키마 강제)으로 불렀다. 총 21회.
- **실행**: gosky AI 서버 컨테이너 안에서 서버에 설정된 키로 호출했다(키 미출력). 사진은 측정 뒤 서버·컨테이너에서 모두 삭제했다.
- **출력 스키마**: `readable`, `reason`, `drugs[]{name, ingredient, perDose, timesPerDay, days, slots[MORNING|LUNCH|DINNER|BEDTIME], timing, confidence}`.
  - 프롬프트로 환자·병원·약국·금액 정보를 출력하지 말라고 지시했다.
  - 표시가 없으면 `slots`를 비우도록 했다.
- **정답**:
  - 사진 속 인쇄 약품명 기준이며, 사용자가 실제 봉투로 확인했다.
  - ②의 `나소프라정500/20m`은 봉투에 잘린 채 인쇄돼 있어 `…20mg`도 정답으로 본다.

## 2. 약 이름 정확 일치 (10종 기준)

| 변형 | opus 5.5 | sonnet 5.5 | haiku 5.5 |
|---|---|---|---|
| 바로 세움 | **9/10** | **9/10** | 4/10 (시간대 틀림) |
| 원본(옆으로 누움) | 7/10 | 6/10 | 2/10 + 없는 약·다른 성분 지어냄 |
| 1024px 축소 | 6/10 | 5/10 (틀린 것 모두 확신 low) | 2/10 + 없는 약 2개 지어냄 |

- 바로 세운 사진에서 opus와 sonnet이 놓친 1건은 같다.
  - `펜클리어맥스정`을 `펜쿨리어맥스정`으로 읽었다(1글자 차이).
  - 이 약은 어느 조합에서도 정확히 읽히지 않았다(인쇄가 작고 흐림).
- **약 개수**: opus·sonnet은 모든 조합에서 빠뜨리거나 더하지 않았다(6종·4종). haiku는 개수가 틀리거나 없는 약을 만들었다.

## 3. 그 밖의 항목

| 항목 | 결과 |
|---|---|
| 하루 횟수·일수 | opus·sonnet 모두 정확(2회·5일 / 2회·3일). haiku는 누운 사진에서 틀림 |
| 1회 복용량 | 반 알(슈다페드정 0.5)을 opus·sonnet이 정확히 읽음 |
| 시간대 | ②의 손글씨 동그라미(아침·저녁)를 opus·sonnet이 정확히 읽음. 표시가 없는 ①은 비워 둠(지어내지 않음). haiku는 틀린 시간대를 넣음 |
| 성분명 | **믿을 수 없음** - opus도 확신 high로 다른 약의 성분을 적은 경우가 2건 |
| 거절 | 합성 메모를 세 모델 모두 `readable=false`로 거절 |
| 확신 표시 | 축소 사진에서는 sonnet이 틀린 항목을 모두 low로 표시했지만, 누운 사진에서는 틀렸는데도 high인 경우가 있었다 → 참고용일 뿐 |

## 4. 처리 시간·비용 (호출 1회, 사진 1장)

| 모델 | 처리 시간 | 비용 |
|---|---|---|

## 5. 결론과 구현 조건

**sonnet 5.5로 진행한다.** 바로 세운 원본 화질에서 opus와 정확도가 같고, 비용은 절반이며 더 빠르다.

구현할 때 지켜야 할 조건 (측정에서 나온 근거 포함):

1. **방향을 바로잡아 보낸다** - 누운 사진은 9/10에서 6~7/10으로 떨어진다. FE가 EXIF 방향을 반영해 업로드하고, 가로로 누운 사진도 감안한다.
2. **화질을 낮추지 않는다** - 1024px로 줄이면 5~6/10이다. 긴 변 약 1500px(API가 내부에서 줄이는 상한 근처)로 보낸다.
3. **haiku 금지** - 사진에 없는 약, 다른 계열 성분을 만들어 냈다.
4. **성분 칸은 결과에서 뺀다** - 틀린 성분이 확신 high로 나온다.
5. **초안만 채운다** - 1글자 오독이 남으므로 보호자가 이름을 확인·수정한 뒤 기존 등록 API(`POST /api/guardian/ward/{wardId}/medication`)로 저장한다. 자동 등록은 하지 않는다.
6. **반 알 처리** - BE `doseAmount`는 정수 1~99라 0.5를 저장할 수 없다. 구현 전에 정할 것.
7. **민감 정보** - 봉투에는 환자 이름·주민번호 앞자리·병원·약국이 있다. 사진은 저장하지 않고 로그에 남기지 않는다. 결과 스키마에 개인정보 칸을 두지 않는다.
8. **확신 표시는 강조용으로만 쓴다** - low 항목을 화면에서 강조하는 데 쓰되, high라고 확인을 건너뛰게 하지 않는다.

## 6. 한계

- 사진 2장(같은 촬영자, 두 양식)뿐이다. 다른 약국 양식·손글씨 위주 봉투·강한 반사는 확인하지 못했다. 구현 뒤 실제 사용 사진으로 다시 확인한다.
- 모델당 조합마다 1회씩만 호출해 결과의 흔들림(같은 사진을 다시 보낼 때 달라지는지)은 재지 않았다.
- effort는 `low`만 측정했다. `medium`이 누운 사진·작은 글씨에서 나아지는지는 모른다.
