## PHASE B. 기능 정합성

### 🟡 M-1 예약 중 진료과만 바꾸면 이전 병원이 남는다 (AI, 재현)

- 저장 초안(병원 `강남메디내과`·진료과 내과·날짜)을 이어 쓰는 턴에 원문 "안과로 할게요"(라우터 규격화 "안과 예약")를 넣으면 진료과만 안과로 바뀌고 병원·`hospital_id`가 그대로 남아 그 병원의 안과 빈 시간을 묻는다(임시 스크립트, 저장소에 남기지 않음). "안과로 예약할게요"처럼 동사가 있으면 새 요청으로 보고 병원을 비운다.
- 실제 예약 서비스에서는 그 병원에 안과가 없으면 빈 시간 조회가 400 `INVALID_DEPARTMENT` → AI가 조회 실패로 보고 시간 직접 입력을 받음 → 예약 생성 `INVALID_DEPARTMENT`로 끝난다.
- 원인: `_clear_stale_links`가 진료과 변경 때 시간만 비운다. 고치기 흐름(`reservation_edit`의 `department`)은 병원까지 비운다 - 두 규칙이 다르다. R-8 이전에도 이력 재구성 경로에서 병원이 남았으나, 초안 저장으로 더 확실히 이어진다.
- **수정안**: 진료과가 바뀌었고 이번 턴에 병원이 따로 정해지지 않았으면 `hospital_name`·`hospital_id`도 비운다(고치기 규칙과 같게). 테스트: 진료과 변경 → 병원 다시 찾기.

### 🟡 M-2 말로 한 시간은 빈 시간 확인 없이 확인 카드로 가고, 생성 때 마감·형식 오류는 막다른 오류다 (AI)

- `_advance`는 `reservation_time`이 비어 있을 때만 빈 시간을 조회한다. "내일 3시"처럼 문장에서 나온 시간(또는 LLM 추출 시간)은 확인 없이 확인 카드로 간다.
- 예약 생성에서 `SLOT_TAKEN`(그 사이 다른 사람이 잡음 포함)·`INVALID_TIME`(30분 칸이 아닌 시각)이 오면 `_RESELECT_PREFIX`에 없어 `tool_error`로 끝난다(`DUPLICATE_RESERVATION`·`PAST_TIME`만 재선택).
- **수정안**: `_RESELECT_PREFIX`에 `SLOT_TAKEN`("그 시간은 이미 마감됐어요…")·`INVALID_TIME`("그 시간에는 예약할 수 없어요…") 추가. 선택: 확인 카드 전에 정해진 시간이 그날 빈 시간에 있는지 한 번 확인.

### 🟢 L-1 빈 시간 조회 400을 "조회 실패"로 본다 (AI)

- `_slots_on`이 200이 아니면 모두 `None`(조회 실패 → 시간 직접 입력)으로 처리한다. `INVALID_DEPARTMENT`(저장 초안의 옛 진료과 이름 - 관리자가 그 사이 이름을 바꿈, M-1 상황)는 진료과를 다시 묻는 것이 맞다. 드문 경우라 낮음.

### 수용한 한계 재확인 (변화 없음)

- 진료과 이름 변경과 동시에 옛 이름으로 들어오는 예약(#5) / 같은 세션 두 요청 겹침(초안은 직전 기록 1건 기준) / 문장 턴 LLM 추출이 이력을 함께 봄(#75 남은 것 - LLM 호출이 필요해 이번 점검에서 재현하지 않음).
