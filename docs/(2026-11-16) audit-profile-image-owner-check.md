## PHASE A. 보안 - 우회 시도

전제: 앱 화면·API 로는 남의 사진 주소를 내 프로필에 넣을 수 없다(사진은 업로드로만 바뀌고, 카카오 가입은 kakaocdn 주소만). 아래는 그 상태가 DB 직접 수정 등으로 생겼을 때 C 가 A 의 파일을 지우려는 시도다. 확인은 **C 의 주소가 아니라 남은 회원 행(A 의 행)** 을 보므로, C 쪽 주소를 바꿔도 A 의 행이 "/파일명"으로 끝나면 막힌다.

| 시도 (C 의 profile_image) | 뽑힌 파일명 | A 의 행 일치 | 결과 |
|---|---|---|---|
| A 와 같은 주소 | `A.png` | 예 | 막힘 - PASS (QA AUTH-A44 로 실측) |
| 다른 경로 `https://파일서버/x/y/A.png` | `A.png` | 예 | 막힘 - PASS |
| 쿼리·조각 붙임 `…/A.png?z=1#f` | `A.png` (`getPath`) | 예 | 막힘 - PASS |
| 호스트 대소문자 `https://FILES…/A.png` | `A.png` | 예 | 막힘 - PASS |
| 퍼센트 인코딩 `…/A%2Epng` | `A.png` (디코딩) | 예 | 막힘 - PASS |
| 끝 슬래시 `…/A.png/` | 빈 값 → null | - | 삭제 자체를 안 함 - PASS |
| 파일명 대소문자 `…/a.PNG` | `a.PNG` | 아니오(LIKE 대소문자 구분) | 파일 서버에 `a.PNG` 삭제 요청 - 파일 서버가 대소문자를 가리면(리눅스 기본) A 파일 무사 - PASS(조건부) |
| 외부 호스트·userinfo·`..` | null | - | 기존처럼 건너뜀 - PASS |

- LIKE 이스케이프: Spring Data 파생 쿼리 `EndingWith` 는 `%`·`_`·`\` 를 이스케이프한다 - 파일명의 `_` 가 와일드카드가 되지 않는다.
- 로그: 건너뛸 때 파일명 끝 6자만 남긴다(주소·회원 id 없음) - 개인정보 아님. PASS.
- 못 막는 범위(설계상): 아무도 안 쓰는 남의 파일(이미 버려진 파일), 파일 서버의 다른 저장처.

## PHASE C. 구조·계약

## 이슈

- 🔴 / 🟠 / 🟡: 없음
- 🟢 L-1: 확인은 "남은 행이 `/파일명`으로 **끝나는가**"다. 파일 서버가 주소 끝에 쿼리(`?v=2` 같은)를 붙여 돌려주는 날이 오면 A 의 행이 일치하지 않아 보호가 조용히 꺼진다. 지금 실제 업로드 주소는 파일명으로 끝난다(QA 실측). `FileServerClientTest` 에 `abc.png?v=2` 예시가 있어 형식이 바뀔 여지를 염두에 둘 것. 제안: `EndingWith("/" + f)` 또는 `Containing("/" + f + "?")` 로 넓히기(넓게 맞으면 "안 지움"으로 기울어 안전).
- 🟢 L-2: 저장된 주소에 퍼센트 인코딩이 있고(`A%20b.png`) C 쪽 주소가 디코딩된 이름으로 맞춰지면 문자열이 달라 일치하지 않는다. 파일 서버가 그런 이름을 만들지 않으면 해당 없음(UUID 계열이면 없음). 제안: L-1 과 함께 인코딩한 이름으로도 한 번 더 확인.
- 🟢 L-3: 업로드 실패 되돌리기 경로 단위 테스트 없음 - `profileImagePersister.replace` 가 던질 때 새 파일 삭제 + 원래 예외 전파를 고정하는 테스트 1개 제안.
