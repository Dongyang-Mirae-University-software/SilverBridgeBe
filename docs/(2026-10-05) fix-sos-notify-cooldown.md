# SOS 알림 쿨다운 30초 → 10초 (2026-10-05)

branch `fix/sos-notify-cooldown-10s` · 마이그레이션 없음

## 1. 변경 이유

- 쿨다운의 목적은 **보호자 폰에 같은 알림이 폭주(alarm fatigue)하는 것을 막는 것**이다. 서버 부하 방어가 아니다
  (알림 executor 포화는 별도 장치가 맡는다).
- SOS에서는 **반복해서 누르는 것 자체가 위급 신호**다. 30초 동안 보호자가 다음 알림을 못 받는 것은 길다고 판단했다.
- FE는 확인 창을 없애고 전송 중 버튼을 비활성화한다(별도 FE 작업). 의도치 않은 중복 탭은 FE가, 의도한 반복 입력의
  알림 간격은 서버 쿨다운이 맡는다.

## 2. 값 비교

| 항목 | 이전 | 이후 |
|---|---|---|
| 알림 쿨다운 | 30초 (코드 상수) | **10초** (`sos.notify-cooldown-seconds`, 환경변수 `SOS_NOTIFY_COOLDOWN_SECONDS`, 기본 10) |
| 허용 범위 | - | 1~300초. 정수가 이 범위 밖이면(0 이하 포함) 기본 10초로 대체 + WARN. **빈 값·비숫자(`KEY=`, `abc`)는 대체되지 않고 기동 실패(BindException, fail-fast)** - 점검 M-1 |
| 같은 피보호자 연타 시 최대 알림 빈도 | 30초당 1회 | 10초당 1회 (최대 3배) |
| 이력(`sos_event`) | 전부 저장 | 변경 없음 |
| 반복 집계 창 | 최근 10분 | 변경 없음 |

## 3. 변경하지 않은 것

- 키 구조(`sos:notify:cooldown:{wardId}`, SET NX EX), 전달 0명이면 해제(SOS-G09), Redis 장애 시 fail-open.
- **푸시·WebSocket·문자 폴백은 단일 쿨다운을 쓴다.** 문자만 별도 간격으로 나누지 않았다.
- SOS 요청 속도 제한(429)은 만들지 않았다. 이상감지 알림 쿨다운(이력 1분·보호자 5분·본인 3분)은 별개다.
- 쿨다운 건너뜀 로그는 DEBUG 유지(연타 시 로그 폭주 방지).

## 4. 영향

- 문자 폴백이 켜진 보호자(FCM 토큰 없음)는 연타 시 문자가 최대 3배 빈도로 나갈 수 있다(과금 포함). 단일 쿨다운을
  유지하기로 한 결정의 대가이며, 문자를 줄이고 싶으면 별도 안으로 다룬다.
- 반복 문구 "(최근 10분 내 N번째)"는 쿨다운을 통과한 알림에만 붙으므로 N이 더 촘촘히 올라간다.
- 동작 변경은 이 값뿐이다. 코드 변경: `SosProperties`(신규), `SosNotificationCooldown`(상수 → 설정 주입), `application.yaml`.

## 6. QA 전달

- `~/SilverBridgeQA/tests/sos/sos.spec.ts`는 테스트 앞에서 `sos:notify:cooldown:{id}` 키를 직접 지우므로 키 이름이 같은
  이번 변경에 **로직 수정은 불필요**하다.
- 쿨다운이 짧아져 "쿨다운 안에서 이력만 남긴다"고 가정한 나머지 SOS 테스트가 **10초를 넘기면 알림이 실제로 발송**된다.
  테스트가 빠르게 이어지면 문제 없으나 느린 환경에서는 알림·문자 발송이 늘 수 있으므로, 실제 SMS를 막으려면
  `E2E_SKIP_SMS=1`을 쓰고 알림이 없어야 하는 검증 앞에서는 `clearSosCooldown()` 대신 간격을 10초 안으로 유지한다.
- QA `README.md`와 `sos.spec.ts`의 "30초 알림 쿨다운" 문구를 "10초"로 정정(별도 저장소 작업).

## 7. FE 전달

- FE 페이지·문구에서 SOS 알림 간격을 "30초"로 안내하는 곳을 "10초"로 정정한다.
- 확인 창 제거 + 전송 중 버튼 비활성화는 별도 FE 작업이며, 이 변경은 그것을 전제로 한다.
